## 改动

- 服务端 `GET /api/models` 每次检查真实文件，提供可用性、大小、版本和模型 URL；只读元数据，不预读全部 GLB。
- 文件存在则按需显示 3D；真实缺失显示“文件尚未提供”；服务不可达与加载错误不再混为缺失。
- 新增/替换模型可在下次查看或“检查模型更新”时发现，不需要重新构建静态可用性表。
- 模型 HTTP 缓存改为 ETag 重新校验；版本变化使用新 URL，过期 URL 返回 409，避免旧 URL 混入新内容。存档 API 不缓存。
- 页面内缓存最近请求的解析场景，同款并发共享一次加载，clone 展示实例、引用计数保护共享材质；以 3 款和 64 MiB 源文件大小作为淘汰预算。正在展示的资源不强制释放；这不是 64 MiB 显存保证。
- 首次显示明确加载占位，准备好后自动切换；整体 25 秒超时，晚到资源可安全释放。
- 关闭展柜详情不再重建背景展柜。其他必要页面重绘保留，取消拆封后的盒体恢复不受影响。
- 不做全模型预加载。现有模型未减面或压缩，因此真正首次打开仍需要传输与解码时间。

## 运行与边界

本副本已包含新前端产物及重新编译的 **Mac ARM64** 服务。用独立存档试用：

```sh
npm start -- --isolated
```

原 main 未合并。依赖暂时复用原项目 node_modules 的符号链接；复制到别的机器需 `npm ci`。

**Windows 和 Mac Intel 服务二进制未重编译**，这些平台应按 `blindbox/server/README.md` 构建新后端后再验收。老服务端可通过单款 HEAD 回退确认存在，但不会获得新清单、版本化共享缓存的完整效果。

版本指纹基于文件大小和纳秒修改时间。普通新增/替换可识别；人为保持相同大小且完全保留修改时间的替换无法识别，应更新文件时间。

没有完成 iPhone/Android 真机、弱网计时或所有 8 款逐个外观验收。存在文件不代表模型资产质量已全部验收。
