# 奇物百货

Aholo 3D AI 黑客松盲盒项目的“奇物百货”店铺前端，当前为第二轮本地功能版本。团队使用 GPT 生成藏品图片，再通过 Aholo Lux3D 制作模型；本仓库负责挑盒、拆封、收藏和展柜体验。

本轮首页改为后方四格系列货架、前方连续暖木柜台和三只米白纸盒，中心盒下方放置主要操作，柜台小牌显示真实价格，下沿提供收藏快捷入口。手机使用当前系列货架、主盒与柜台操作区重新排布。展柜采用三个固定陈列位置，选中铭牌后才显示编辑控件。保留第一版的业务流程与数据保护，奖池沿用当前服务的四个系列、28 款藏品，以及服务中的价格、抽取规则和 SQLite 收藏存档。

**当前奖池为 28 款，模型已全部到位。** 深夜食堂、打工动物、怪奇家电、旧梦玩具各 7 款；旧梦玩具使用 `vt-01`～`vt-07`，已替换原奶蛙系列。收藏预览优先使用现有缩略图，新增玩具模型的缩略图按需自动生成并缓存。文件齐全不等于已完成所有模型的真机外观验收。

首页四格货架使用本轮生成的四张透明手绘风 PNG，全部标为“系列示意”，仅表达系列气质，不代表实际奖品。货架中不使用模型缩略图或 SVG 替代插画；下沿收藏快捷条与收藏列表仍根据已获得藏品显示对应真实模型缩略图。实际抽取身份、结果页及展柜继续使用服务数据和对应 GLB。

正常启动会从 `blindbox/server/` 的 C++ 源码增量编译服务；修改 `game_config.cpp` 后再次启动即可生效。运行程序和编译缓存位于 Git 忽略的本地目录，沿用原来的 SQLite 数据库，不改变概率、价格或重复款处理。当前服务没有连续次数保底，只有同系列、同稀有度的历史防重复。

## 本地体验

需要 Node.js 22.12 或更高版本，以及本机 C++ 编译器。macOS 可执行 `xcode-select --install` 安装 Apple 命令行工具；Windows 使用 Visual Studio C++ 工具或 MinGW，启动器会调用现有编译脚本。实际验证平台为 macOS Apple Silicon。

在仓库根目录执行：

```sh
npm ci
npm run build
npm start
```

打开终端打印的地址，通常是 <http://127.0.0.1:8765/>；端口已占用时服务会尝试后续端口。关闭最后一个游戏网页后约 5 秒，服务自动退出；刷新页面或切到后台不会退出，其他游戏标签页还开着时也不会退出。启动后 90 秒没有网页连接时也会自动结束。

macOS 可右键打开根目录的 `启动奇物百货.command`，Windows 双击 `启动奇物百货.bat`；两者都会自动安装缺失依赖、构建网页与服务并打开浏览器。旧的 `blindbox/启动游戏.command` 和 `.bat` 在完整源码目录中会转到新入口。Mac 从 Finder 打开的独立 Terminal 窗口会在游戏结束后自动收起；已有终端中的其他任务、其他标签页不受影响。

正常启动沿用 `blindbox/data/blindbox-save.db`。需要体验或测试而不触碰已有收藏时，使用：

```sh
npm start -- --isolated
```

隔离模式每次新建一份临时存档，启动日志会打印完整路径。它不会读取、重置或覆盖正常存档。

## 存档与读档

点击页面顶部的「存档」，或在「偏好与店内说明」中点击「管理存档与读档」。当前游戏仍会自动保存，不需要每次退出前手动操作。

- 有三个可命名的手动存档位，可保存、覆盖、读取和删除；后续游玩不会改变已经保存的记录。
- 每份记录包含金币、仓库、展柜收藏、待收纳结果、抽盒统计、历史收集记录，以及保存时的三个展柜位置、朝向和声音／动效偏好。
- 覆盖、读档和删除都要在弹窗中确认。读档前会自动保留一份「读档前的进度」，可以恢复；这份备份只保留最近一次。
- 删除手动记录会腾空该存档位，当前游戏进度和其他存档保持原样。
- 想从头开始时，在存档管理底部的「全新开局」点击「重新开局」并确认。金币按当前配置恢复，收藏、待收纳结果、展柜摆放和抽盒记录清空；声音／动效偏好与三个手动存档保留。重置前会保存一份自动备份，可在「最近一次读档或重置前的备份」恢复。
- 存档位与自动保存都在原来的 `blindbox/data/blindbox-save.db` 中。新增的 `save_slots` 表兼容已有数据库，不会重置旧金币和收藏；记录保存在本机，换电脑前请自行备份。

## 体验流程

1. 点击后方系列货架，再挑柜台上的包装盒，点击“拆这盒”；选盒不扣金币。
2. 向右拖动封条，或用“拆开看看”按钮／键盘开封。实际扣费与结果由原服务一次性保存。
3. 拆封结算完成后立即显示名称和收纳按钮，左侧纸盒动画与三维模型继续播放、加载。动画中点击收纳、放入展柜或「收好，再拆一盒」，会立即跳过动画并执行操作。关闭、刷新或模型重试都继续保留同一结果。
4. 将藏品收进收藏仓库，或按原有规则收入展柜。同款展柜最多一件，重复实物可留在仓库。
5. 在“我的展柜”点击一个位置的铭牌，从已收入展柜的款式中选择并调整朝向；更换位置不会复制库存或再次扣费。

声音默认关闭；“偏好与店内说明”中可开启声音、减少动效并查看真实奖池概率。陈列位置、朝向和偏好平时保存在当前浏览器；手动存档会将它们与金币、藏品一起写入本机 SQLite，读档时一起恢复。

## 开发与检查

沿用 Vanilla JavaScript、Three.js 与 Vite。当前前端源码位于根目录 `web/`，构建输出到 `blindbox/dist/`。owner 补传中的旧前端位于 `blindbox/web/`，保留供参考，不应覆盖当前前端。C++ 服务源码位于 `blindbox/server/`，自动编译到 `blindbox/server/build/dev/`，启动器再运行 `.local/runtime/` 中的副本，避免生成的程序混入 Git 变更。

```sh
npm test          # 请求互斥、未知结果恢复、陈旧结果防护等客户端检查
npm run test:api  # 临时存档上的真实服务检查，不调用原存档
npm run test:saves # 存档兼容、重启恢复、删除、并发覆盖和读档备份
npm run test:session # 多标签页、刷新、后台页和约 5 秒自动退出
npm run test:start # 新启动器的退出传递、常驻模式与隔离存档
npm run build    # 生成供本机服务使用的网页
```

开发时先执行 `npm start -- --keep-alive` 启动常驻本机服务，再在另一个终端执行 `npm run dev`。常驻模式由 `Ctrl+C` 结束，方便前端开发时多次打开或关闭网页。Vite 默认将 `/api` 和 `/models` 转发到 `http://127.0.0.1:8765`；若服务使用其他端口，请相应修改 `vite.config.js`。

## 接入团队模型

将模型放入 `blindbox/models/`，文件名与 `/api/config` 的 `item.model` 一致：深夜食堂 `ms-01.glb`～`ms-07.glb`、打工动物 `wa-01.glb`～`wa-07.glb`、怪奇家电 `wd-01.glb`～`wd-07.glb`、旧梦玩具 `vt-01.glb`～`vt-07.glb`。优先使用纹理内嵌的 GLB；当前未配置 Draco／KTX2 解码器。

模型到位后可在原藏品详情点击“检查模型更新”，无需重新抽盒。首次显示不会为已知缺失项反复请求文件；手动重试仍会访问该藏品原模型地址。新增资源后应逐款核对实际外观、中心、比例、纹理与移动设备性能，并更新资源清单（运行时可用性由服务自动检测）；不要只用文件存在与否判断 3D 验收完成。

收藏卡片优先显示现成的真实模型缩略图。新增模型尚无缩略图、图片加载失败，或模型文件大小与原预览记录不一致时，会在卡片进入可见区域后自动渲染透明预览；同款共享任务，任务串行执行，离开页面后未开始的任务会取消。生成结果按模型版本保存在浏览器缓存，不用先点击详情；模型加载与详情共用缓存，不会再次抽取、扣费或改动存档。

运行 `node scripts/render-thumbnails.mjs` 可打开 <http://127.0.0.1:5197/> 资源工作台。它不连接游戏 API 或存档；保存按钮会把对应真实 GLB 的 512×512 透明 PNG 写到 `web/public/thumbnails/`。本轮原始模型约 9–20 MB，尚未压缩；首页货架用系列插画、收藏快捷条用真实缩略图，避免同时加载全部模型。

空木格素材只负责木材、灯光与空间背景。系列文字、价格、按钮、可选纸盒、抽取结果和收藏数量均由真实页面组件与数据渲染；没有把整张概念图当作页面。
