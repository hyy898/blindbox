# 开盲盒 · 纯抽盒版（blindbox5）

每位队友从同一个 GitHub 仓库获取代码，在自己的电脑上运行开发模式。启动一次后，保存源码会自动更新当前游戏网页。

## 首次准备

需要 Node.js **22.12 或更高版本**、Git，以及本机的 C++17 编译器。

- macOS：安装 Apple 命令行工具：`xcode-select --install`。
- Windows：安装 MSYS2 的 UCRT64 g++，或 Visual Studio 的“使用 C++ 的桌面开发”组件。编译脚本会查找常见安装路径。
- Linux：准备 gcc/g++ 和常规构建工具。

在团队仓库的本地副本中运行：

```sh
npm ci
npm run dev
```

也可以双击根目录 `开发模式.command`（macOS）或 `开发模式.bat`（Windows）；首次会自动安装依赖。开发模式会打印并打开本机地址，默认从 `http://127.0.0.1:5173/` 开始选择可用端口。

## 平时怎么修改

| 要改的内容 | 修改位置 | 保存后的行为 |
|---|---|---|
| 盲盒、手办、掉率、价格、开局金币 | `server/src/game_config.cpp` | 自动编译 C++、重启开发服务、刷新原网页 |
| C++ 规则和接口 | `server/src/` | 同上 |
| 网页布局、交互、样式 | `web/src/`、`web/index.html` | Vite 自动更新 |
| 3D 模型 | `models/<手办id>.glb` | 自动刷新网页 |

编译错误或配置错误会显示在终端和浏览器。上一版服务会保持运行；修正后再次保存即可恢复。连续保存会合并等待编译，不会同时启动多个编译器。

开发模式会持续监听文件，结束开发时在窗口按 **Ctrl+C**。再次双击开发启动器会复用本项目已经运行的开发服务。

开发存档为 `data/dev-save.db`，试玩存档为 `data/blindbox-save.db`，两者独立。刷新和自动重启会保留进度。**初始金币只作用于新开局**；测试修改后的开局金额时，点击游戏里的“重置进度”，这会清空当前开发存档的收集进度。

## GitHub 协作

私有仓库同样适用，不需要公开。使用团队已有仓库和已有提交历史即可。

1. 开始修改前同步团队的最新代码。
2. 每个任务创建自己的分支，例如 `feature/new-box`。
3. 保存源码，在本地开发网页验证效果。
4. 提交并推送自己的分支，在 GitHub 发起 Pull Request。
5. 合并后，其他队友拉取最新代码；已经运行的开发模式会检测文件变化并更新。

例如，已经检出团队仓库时：

```sh
git pull --ff-only
git switch -c feature/new-box
# 修改并测试后
git add server/src/game_config.cpp
git commit -m "Add a new blind box series"
git push -u origin feature/new-box
```

保存只更新自己的本地游戏，不会自动提交或覆盖队友代码。依赖文件 `package.json` / `package-lock.json` 变化后，结束开发模式，重新执行 `npm ci` 再启动。

`.gitignore` 已排除个人存档、`node_modules/`、编译缓存、平台可执行文件和构建产物。提交 `web/`、`server/src/`、编译脚本、`package.json`、`package-lock.json` 和需要共用的模型。模型清单 `models/README.txt` 会自动生成，不需要提交。

`.gitattributes` 已约定脚本换行格式，方便 macOS / Windows 一起开发。不要在本机删除被忽略文件来“整理 Git”，这些文件可能包含个人存档。

## 构建与试玩

```sh
npm run build         # 将 web/ 构建到 dist/
npm run build:server  # 编译本机 C++ 服务器
npm test              # 抽盒/收藏/迁移规则 + 开发模式集成测试
```

正常试玩继续双击 `启动游戏.command` / `启动游戏.bat`。源码目录中它会自动检查并构建前端，再启动 C++ 程序；关闭最后一个游戏网页后仍会自动退出。开发模式使用独立的可执行文件，不会因为重新编译而结束试玩服务器。

`dist/` 和可执行文件可作为试玩产物分发；可编辑前端源码以 `web/` 为准。当前目录如果尚未绑定 Git 远程，需要先接入团队的私有仓库，再提交本次文件。

## 本版玩法

导航只有“抽盲盒 / 仓库 / 展柜”。花金币开盒，手办可以放进展柜、放入仓库或卖掉；所有配置的款式都进入展柜后通关。没有顾客委托、代抽、自费履约、小店装扮、代币奖励或兑换商店。

每盒按所属系列的概率独立抽取，没有连续抽取保底。同一系列、同一稀有度内优先开出从未拥有过的款式，可用 `noDupeUntilOwned` 开关控制。

| 系列 | 普通 | 稀有 | 史诗 | 隐藏款 |
|---|---:|---:|---:|---:|
| 深夜食堂 | 60% | 30% | 8.5% | 1.5% |
| 打工动物 | 60% | 25% | 12% | 3% |
| 怪奇家电 | 68% | 22% | 6% | 4% |
| 奶蛙一家 | 73% | 20% | 5% | 2% |

奶蛙有两款等权重史诗，各 2.5%；隐藏款保持在其下。启动时会检查隐藏款的单款概率不能高于其他可抽款式。

新增系列时，`Series` 初始化末尾填写独立概率表，合计必须为 1：

```cpp
{"your-series", "新系列", 100, 1.0, {
    // 手办列表……
}, {{"common", .60}, {"rare", .30}, {"epic", .085}, {"secret", .015}}},
```

省略独立表时使用 `cfg.rarities` 中的默认掉率。单款基础概率为“系列稀有度掉率 × 该款权重 / 同稀有度总权重”；启用防重复时，按当前尚未拥有的同档候选池重新分配权重。

## 从 4 复制过来的存档

不用重置。金币、仓库、展柜、曾拥有记录、待安置手办和开盒统计保留。旧进行中委托结束，已支付的个人垫款或旧版冻结保证金退回一次；顾客未使用的预算不会计入个人金币。下次保存时删除委托、代币和旧保底字段。

本目录的服务和存档独立于 `blindbox 4`；复制过来的开发会话记录不会复用旧目录的服务。

验证命令：`npm test`；编译后运行 `python3 server/tests/api_test.py`。接口字段见 `docs/api.md`。
